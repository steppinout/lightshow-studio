# Clean-room policy

This project is committed to a clean-room development process.

## Core rule

No source code, assets, markup, UI text, or behavior from xLights, LOR, or any GPL-licensed sequencer is copied into this project.

## Explicit restrictions

- no copied GPL code
- no copied xLights code
- no copied LOR code
- no copied assets or art
- no copied layouts, prop images, or visual UI elements from existing products
- no copied UI strings that were written for a competing sequencer
- no reuse of proprietary implementation logic or vendor-specific structure when a clean independent implementation is feasible

## Compatibility is separate from copying

The project may support import/export compatibility with other ecosystem formats, but that compatibility must be implemented through independently written logic.

Examples:

- FSEQ export generated by our own code
- xLights import readers written from public format understanding and independent implementation
- future LOR import support built from our own analysis and parser code

Compatibility is a product feature, not a license exception.

## Provenance tracking for research

Research materials and sequence samples may be used as reference and analysis inputs only. They are not source code and must not be copied into the repo as working project assets.

The repository will maintain clear provenance notes for any externally sourced examples, including:

- research purpose
- source description
- date of review
- whether content is aggregate-only or sample-only
- whether it was used for statistical analysis only

## Research-only status

Any sequence packages, sample archives, or third-party project files are treated as research data only and are not part of the project source tree.

This includes:

- archive files
- sample sequences
- imported data sets
- vendor-generated project files

Only aggregate summaries and notes are kept in the repository when they are useful for product design decisions.

## Compliance standard

Before merging or publishing functionality, the team must confirm:

- the feature was implemented independently
- no GPL or copied code paths were introduced
- import/export compatibility remains clearly documented as interoperability only
- research files remain separated from source material

The project must remain transparent about what is original, what is compatibility logic, and what is research-only material.
